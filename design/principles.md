# weed 设计原则

> 组件可以长在任何地方，但长得像 weed 的组件只有这几条约束。
> 改动这里之前，先看 [decisions.md](./decisions.md) 里有没有相关记录。

## 0. 一句话

**weed 是终端，不是画册。** 界面先像工具，再像设计。

---

## 1. 字面优先

- 拉丁字符用 **Departure Mono**（像素等宽），界面、数据、标签、按钮、正文全部 mono。
- **中文永不落到宋体**：mono 栈里中文回落 PingFang SC /  Hiragino Sans GB / Microsoft YaHei。
- 衬线（Source Serif 4）只允许出现在一种地方：少量拉丁引文与 hero 的强调词。
  衬线出现超过一处，就是设计退化了。

> 理由：mono 是"工具"的直觉，衬线是"读物"的直觉。weed 想做前者。

## 2. 描边而不是边框

- 所有分隔用 **1px 内描边**（`box-shadow: inset 0 0 0 1px var(--line)`），不用 `border`。
  内描边不占布局宽度，1px 线在深底上不会因边框偏移而糊掉。
- 描边分两级：`--line`（普通分隔）与 `--line-strong`（输入框、可点击边界）。
- 圆角上限 **3px**。超过 3px 就不是 IDE 了。

## 3. 面板是实心的

- 深色主题下面板（`--panel`）是**实底**（灰蓝 `#1e2530`），不是半透明。
  半透明在多层嵌套后会变成一片糊。
- 层次靠 `--panel-soft` 和 `--background` 两级实色拉开，不靠模糊。

## 4. 网格要能感觉到，看不见

- 蓝图网格是氛围，不是花纹：小格 20px、大格 100px，透明度 3% / 6%。
- 网格永远在最底层，永远不抢内容的注意力。

## 5. 双主题靠变量，不靠组件

- 主题切换是 `<html data-theme="dark|light">` 换一组 CSS 变量。
  **组件代码里不允许出现任何主题判断。**
- 首帧不能闪：bootstrap 脚本内联进 `<head>`，先读 localStorage，再看系统偏好。

## 6. 源码落地，不管版本

- weed 不发 npm 包。装 = 复制源码进你的仓库，从此归你。
- 组件必须**自包含**：主题 token、`cn()`、npm 依赖跟着组件一起走。
  一条 URL 安装、零配置，是硬指标。

## 7. 文档是给人和 agent 一起看的

- 每个组件页都要有：什么时候用 / 什么时候别用、解剖、变体表、API 表、源码。
- 站点同时提供 `llms.txt`、`llms-full.txt` 和每页的 `.md` 孪生版本。
  agent 能读到的东西，人也得能读到。

## 8. 宁缺毋滥

- 11 个组件，其中 10 个是常规件，1 个（BlueprintGrid）是签名件。
- 不为了凑数加组件。一个用不上的组件是负债。

---

## 修订规则

改动这份文档 = 改设计语言。必须同时：

1. 在 [decisions.md](./decisions.md) 记一条决策（含状态与理由）；
2. 更新 `packages/tokens/tokens.json`（如果涉及 token）；
3. 跑 `pnpm tokens:build && pnpm build`。
